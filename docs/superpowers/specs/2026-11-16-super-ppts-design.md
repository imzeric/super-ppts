# super-ppts 现行合同：四步成稿

状态：用户于 2026-11-16 提出四步流程并要求在同一分支继续实现。本文件取代首版「确认大纲后立即物化整套幻灯片」的路径。首版的原生形状、连接线端点绑定和图表工作簿要求仍然有效。

## 四步

1. 用户输入背景。系统生成 Markdown 大纲。原文可编辑、可预览、可保存并在重新加载后仍在。优化只产生候选，采用后才替换。语法有明确边界；诊断带行号。有诊断时不能确认。
2. 用户明确确认大纲后，才单独生成每页可编辑文字。这一步不画图、不导出完整视觉对象。文字可改，再单独确认。
3. 用户在幻灯片上手工添加、移动、缩放占位框，并填写标题、画面描述、绘图说明和输出类型。一页可以有多个占位。位置和内容持久化。绘制前导出时，占位是带这些文字的原生形状，不是图片。系统不得自动替用户摆放或一次性替换全部占位。
4. 用户明确选择全部或一部分占位后批量绘制。每一项有状态、错误，失败项可单独重试。已成功的项在非强制重试时跳过，不覆盖。绘制可以在项与项之间取消，未开始的项保持原状。结果在界面和 PPTX 里仍可编辑；插图除外，插图明确标为位图。

## Markdown 语法

- 第一个内容行是 `# 文稿标题`。
- 每张幻灯片以 `## 标题` 开始，最多 8 张。界面说明这是为了分步核对。
- 可选 `<!-- id: 英文编号 -->`，演示稿会写上，优化时必须保留。
- `kind: title | bullets | table | diagram | chart`。
- 图还要 `diagram: flow | org | architecture | relation`，以及至少两个 `- 节点`。
- 表格和图表使用 `|` 表格。图表还要 `chart: bar | line | pie`，第二列是数字。饼图只能有一个系列。
- 不认识的 kind、缺表、列数不一致都是诊断，不静默丢弃。

## 输出类型

原生，来自结构化语义而不是整页图片：

- `diagram-flow` 流程图、`diagram-org` 组织图、`diagram-architecture` 架构图、`diagram-relation` 关系图。它们共用 Diagram IR。关系图把第一个节点连到其余节点。架构图从左到右。导出仍是 `p:sp` 与带 `stCxn` / `endCxn` 的 `p:cxnSp`。
- `chart-bar`、`chart-line`、`chart-pie`。导出是图表部件和嵌入工作簿。
- `table`。导出是 `a:tbl`。

位图：

- `illustration` 只在用户选择插图时调用生图。结果是 PNG/JPEG 图片部件，界面和导出说明写明「位图，内部像素不可逐项编辑」。不把位图内部标成可编辑形状，也不做图片还原成原生对象。

独立图编辑器保留。绘制出的图可以打开编辑，也可以把已有图放进占位。

## 过期与保留

大纲在确认后若 Markdown 变化，大纲回到草稿，文字稿和占位标为待核对，但不删除占位的位置、尺寸和已绘制结果。文字确认后若再改文字，占位同样标为待核对。导出在大纲未确认、文字未确认或仍有待核对项时返回 409。用户可以按「保留现有文字和占位」明确清掉待核对标记，这不会改坐标，也不会重画。

## 模型配置

三种能力分开：`text` 文本规划、`vision` 视觉理解、`image` 插图生成。每种有地址、模型名和密钥。

- 文本与视觉：`POST {base}/chat/completions`。视觉的 user content 是数组，包含 `text` 和 `image_url`（data URL）。只写模型名不算视觉。
- 插图：`POST {base}/images/generations`，请求 `response_format: b64_json`，只接受 PNG 或 JPEG。
- 地址只允许 https；本机 `127.0.0.1` 和 `localhost` 允许 http。地址里不能带账号密码。重定向直接失败。超时 30 秒。
- 密钥只存在服务端 SQLite 或环境变量 `AI_TEXT_*`、`AI_VISION_*`、`AI_IMAGE_*`。旧的 `AI_BASE_URL`、`AI_API_KEY`、`AI_MODEL` 只作为文本能力的后备。GET 只返回掩码和来源，不返回密钥。保存时密钥留空不覆盖。清除密钥是单独动作。
- 没有文本密钥时是演示模式，界面写明，不访问网络。在线模式失败不会改用演示稿或演示位图。

本机单用户。密钥明文在本地数据库，没有额外加密，因为没有登录边界。不要把进程暴露到不受信任的网络。

## 非目标
